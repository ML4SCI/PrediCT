# D033.1 Amendment: what counts as a broken draw

**Date**: 2026-10-04
**Stage**: stability
**Status**: Active (amends D033; D033's gate rule, threshold and 5% allowance are unchanged)
**Module**: `scripts/04b_realistic_perturbations.py` (`_extract_draw`), `scripts/05b_icc_gate_realistic.py`

## Decision

A draw is **broken** only when, after the draw's perturbations, the mask is empty or below PyRadiomics' own ROI minimums (`minimumROISize` 14, `minimumROIDimensions` 1, read from the locked `params.yaml` by `predict.features.radiomics.roi_too_small`), decided before extraction; or when an extracted feature value is NaN. Broken draws are what D033's 5% rule counts.

"Below the minimums" means exactly what PyRadiomics rejects: a voxel count at or below `minimumROISize` (PyRadiomics tests `roiSize <= minimumROISize`, so a 14-voxel mask is broken and a 15-voxel mask is not), a single voxel, or fewer axes with extent > 1 than `minimumROIDimensions`. The first implementation used `<` for the size test; a 14-voxel perturbed mask (pid 32, arm S3) would then have raised inside PyRadiomics and been recorded as an error. Corrected 2026-10-04 before any stage 4 result was produced; a test pins the boundary against PyRadiomics itself.

Any other exception during a draw (in the polygon jitter, canonical features, volume perturbation or the extractor itself) is an **error**. An error fails the patient: stage 4b exits 1 and writes no `COMPLETE.json`, and stage 5b refuses to gate on any draw with status `error`.

## Rationale

D033 says a draw is broken "if extraction fails (for example the mask drops below `minimumROISize` 14, D009) or a feature is NaN". The implementation read "extraction fails" as any `ValueError` from the extractor, and recorded every other exception as a draw error that stage 5b then treated as a missing observation under the same 5% allowance. A test reproduced a feature passing with ICC 1.0 despite an unexpected error. The intent of D033, shown by its example, is mask dropout under perturbation: a property of the data. A software or input error is not a property of the feature's stability and must not be absorbed by the allowance.

Fixed before the stage 4 run that produced the reported gate; no gate result under the looser reading is used.

## Alternatives considered

- **Keep the looser reading.** Rejected: it lets a bug lower the denominator silently.
- **Treat every extraction failure as an error, including small ROIs.** Rejected: mask dropout under perturbation is the designed, counted outcome in D033.
